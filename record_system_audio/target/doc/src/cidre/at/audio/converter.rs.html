325/// When using AudioConverterFillComplexBuffer() (either a single call or a series of calls), some
326/// conversions, particularly involving sample-rate conversion, ideally require a certain
327/// number of input frames previous to the normal start input frame and beyond the end of
328/// the last expected input frame in order to yield high-quality results.
329///
330/// These are expressed in the leadingFrames and trailing_frames members of the structure.
331///
332/// The very first call to AudioConverterFillComplexBuffer(), or first call after
333/// AudioConverterReset(), will request additional input frames beyond those normally
334/// expected in the input proc callback to fulfill this first AudioConverterFillComplexBuffer()
335/// request. The number of additional frames requested, depending on the prime method, will
336/// be approximately:
337///
338/// Prime method                  | Additional frames
339/// ------------------------------|----------------------
340///          PrimeMethod::Pre     | leading_frames + trailing_frames
341///          PrimeMethod::Normal  | trailing_frames
342///          PrimeMethod::None    | 0
343///
344/// Thus, in effect, the first input proc callback(s) may provide not only the leading
345/// frames, but also may "read ahead" by an additional number of trailing frames depending
346/// on the prime method.
347///
348/// PrimeMethod::None is useful in a real-time application processing live input,
349/// in which case trailing_frames (relative to input sample rate) of through latency will be
350/// seen at the beginning of the output of the AudioConverter.  In other real-time
351/// applications such as DAW systems, it may be possible to provide these initial extra
352/// audio frames since they are stored on disk or in memory somewhere and
353/// PrimeMethod::Pre may be preferable.  The default method is
354/// PrimeMethod::Normal, which requires no pre-seeking of the input stream and
355/// generates no latency at the output.
356#[derive(Debug, Eq, PartialEq, Clone, Copy)]
357#[repr(C)]
358pub struct PrimeInfo {
359    /// Specifies the number of leading (previous) input frames, relative to the normal/desired
360    /// start input frame, required by the converter to perform a high quality conversion. If
361    /// using kConverterPrimeMethod_Pre, the client should "pre-seek" the input stream provided
362    /// through the input proc by leadingFrames. If no frames are available previous to the
363    /// desired input start frame (because, for example, the desired start frame is at the very
364    /// beginning of available audio), then provide "leadingFrames" worth of initial zero frames
365    /// in the input proc.  Do not "pre-seek" in the default case of
366    /// PrimeMethod::Normal or when using PrimeMethod::None.
367    pub leading_frames: u32,
368
369    /// Specifies the number of trailing input frames (past the normal/expected end input frame)
370    /// required by the converter to perform a high quality conversion.  The client should be
371    /// prepared to provide this number of additional input frames except when using
372    /// PrimeMethod::None. If no more frames of input are available in the input stream
373    /// (because, for example, the desired end frame is at the end of an audio file), then zero
374    /// (silent) trailing frames will be synthesized for the client.
375    pub trailing_frames: u32,
376}

442/// Callback function for supplying input data to AudioConverterFillComplexBuffer.
443///
444/// This callback function supplies input to AudioConverterFillComplexBuffer.
445/// The AudioConverter requests a minimum number of packets (*ioNumberDataPackets).
446/// The callback may return one or more packets. If this is less than the minimum,
447/// the callback will simply be called again in the near future. Note that ioNumberDataPackets counts
448/// packets in terms of the converter's input format (not its output format).
449///
450/// The callback may be asked to provide multiple input packets in a single call, even for compressed
451/// formats. The callback must update the number of packets pointed to by ioNumberDataPackets
452/// to indicate the number of packets actually being provided, and if the packets require packet
453/// descriptions, these must be filled into the array pointed to by outDataPacketDescription, one
454/// packet description per packet.
455///
456/// The callback is given an audio buffer list pointed to by ioData.  This buffer list may refer to
457/// existing buffers owned and allocated by the audio converter, in which case the callback may
458/// use them and copy input audio data into them.  However, the buffer list may also be empty
459/// (data_byte_size == 0 and/or data == NULL), in which case the callback must provide its own
460/// buffers.  The callback manipulates the members of io_data to point to one or more buffers
461/// of audio data (multiple buffers are used with non-interleaved PCM data). The
462/// callback is responsible for not freeing or altering this buffer until it is called again.
463///
464/// For input data that varies from one packet to another in either size (bytes per packet)
465/// or duration (frames per packet), such as when decoding compressed audio, the callback
466/// should expect outDataPacketDescription to be non-null and point to array of packet descriptions,
467/// which the callback must fill in, one for every packet provided by the callback.  Each packet must
468/// have a valid packet description, regardless of whether or not these descriptions are different
469/// from each other.  Packet descriptions are required even if there is only one packet.
470///
471/// If the callback returns an error, it must return zero packets of data.
472/// AudioConverterFillComplexBuffer will stop producing output and return whatever
473/// output has already been produced to its caller, along with the error code. This
474/// mechanism can be used when an input proc has temporarily run out of data, but
475/// has not yet reached end of stream.
476#[doc(alias = "AudioConverterComplexInputDataProc")]
477pub type ComplexInputDataProc<const N: usize = 1, D = c_void> = extern "C-unwind" fn(
478    converter: &Converter,
479    io_number_data_packets: &mut u32,
480    io_data: &mut audio::BufList<N>,
481    out_data_packet_descriptions: *mut *mut audio::StreamPacketDesc,
482    in_user_data: *mut D,
483) -> os::Status;
484
485#[doc(alias = "AudioConverterComplexInputDataProcRealtimeSafe")]
486pub type ComplexInputDataProcRealtimeSafe<const N: usize = 1, D = c_void> =
487    extern "C-unwind" fn(
488        converter: &Converter,

490        io_data: &mut audio::BufList<N>,
491        out_data_packet_descriptions: *mut *mut audio::StreamPacketDesc,
492        in_user_data: *mut D,
