29    /// the context's fill color.
30    ///
31    /// Value must be a &cf::Boolean. Default is false. The reason
32    /// why this exists is because an NSAttributedString defaults to a

34    /// set the color in the context. This will allow developers to
35    /// sidestep this, making CoreText set nothing but font information

45    ///
46    /// Value must be a &cf::Number float. Default is standard kerning.
47    /// The kerning attribute indicate how many points the following
48    /// character should be shifted from its default offset as defined
49    /// by the current character's font in points; a positive kern
50    /// indicates a shift farther along and a negative kern indicates a
51    /// shift closer to the current character. If this attribute is not
52    /// present, standard kerning will be used. If this attribute is

60    ///
61    /// Value must be a &cf::Number. Default is zero (no tracking).
62    /// The tracking attribute indicates how much additional space, in
63    /// points, should be added to each character cluster after layout.
64    /// The effect of this attribute is similar to kCTKernAttributeName
65    /// but differs in that the added tracking is treated as trailing
66    /// whitespace and a non-zero amount disables non-essential ligatures
67    /// unless overridden by kCTLigatureAttributeName being present.
68    /// If both kCTKernAttributeName and kCTTrackingAttributeName are
69    /// present kCTKernAttributeName will be ignored unless zero;
70    /// kCTTrackingAttributeName will still be honored.

76    /// Controls ligature formation.
77    ///
78    /// Value must be a &cf::Number. Default is int value 1. The ligature
79    /// attribute determines what kinds of ligatures should be used when
80    /// displaying the string. A value of 0 indicates that only ligatures
81    /// essential for proper rendering of text should be used, 1
82    /// indicates that standard ligatures should be used, and 2 indicates
83    /// that all available ligatures should be used. Which ligatures are
84    /// standard depends on the script and possibly the font. Arabic
85    /// text, for example, requires ligatures for many character
86    /// sequences, but has a rich set of additional ligatures that
87    /// combine characters. English text has no essential ligatures, and
88    /// typically has only two standard ligatures, those for "fi" and
89    /// "fl" -- all others being considered more advanced or fancy.
90    /// On iOS releases prior to 6.0 essential ligatures are applied
91    /// iif the font contains glyphs for any of U+FB00 through U+FB04 and
92    /// the font lacks AAT or OpenType shaping tables, but as of 6.0
93    /// shaping tables (or the lack thereof) are treated as definitive.
94    #[inline]
95    pub fn ligature() -> &'static Self {
96        unsafe { kCTLigatureAttributeName }
97    }
